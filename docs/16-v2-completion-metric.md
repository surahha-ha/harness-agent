# v2 완료 측정 — 작업 단위와 "개입 없이 완주" 의 정의

> **성격: 규범 문서.** 로드맵(`08`)이 v2 의 완료를 "개입 없이 완주한 작업 비율 상승의 실측" 으로
> 정해 두었는데, 그 비율의 **분모(작업)와 분자(개입 없음·완주)가 어디에도 정의돼 있지 않았다.**
> 이 문서가 그것을 고정한다. 구현이 못 미친다고 조용히 낮추지 않는다 — 바꿀 때는 결정 이력에
> 근거를 적고 바꾼다(`07`·`15` 와 같은 규칙).
>
> 결정 이력: 2026-09-01 — 최초 작성. 입력 = 로드맵 v2 정의 · 리서치 1 §3(완주율 = 검증 게이트
> 그린으로 종료한 작업) · `docs/13` §2·§3 · 한 설치처의 실로그(하네스 로그 3641건 + 세션
> 트랜스크립트 73세션·701턴, 건수만 반출). **작업 단위 후보 셋을 실데이터로 반증한 뒤** 골랐다.

## 1. 문제 — 비율의 분모가 없었다

`docs/15` §9 는 v2 전체의 완료를 로드맵 정의에 미뤘고, "그 분모·분자가 바로 §5 가 끊기지 않게 지킨
관찰 기록" 이라고 썼다. 실로그를 열어 보니 그 관찰 기록엔 **작업을 가를 열쇠가 없었다**:

- `session` 필드 = **0건 / 3641건.** 스키마(`13` §3)는 "환경이 주면 싣는다" 였고 구현은 환경변수
  하나를 봤는데, 환경은 그것을 **훅 페이로드(stdin JSON)** 로 준다. 규범은 옳았고 구현이 잘못된 곳을
  봤다 — F26 과 같은 형태의 미이행이라 코드를 고쳤다(§4).
- 그래서 지금까지의 지표는 전부 **이벤트 단위**였다. 발동 15 · pass 3400 은 셀 수 있어도
  "몇 개의 작업 중 몇 개가 개입 없이 끝났나" 는 물을 수 없었다.

## 2. 작업 단위 후보 셋 — 실데이터 반증

| 후보 | 얻는 법 | 실측 (한 설치처, 2주) | 판정 |
| - | - | - | - |
| **세션** | 페이로드 `session_id` | 73세션, 세션당 턴 중앙값 8·최대 40 | 너무 굵다 — 한 세션에 위임이 여러 번 |
| **커밋** | 셸 명령의 `git commit` 관찰 | 701턴 중 커밋 있는 턴 61 | 턴의 부분집합. "커밋 안 한 작업" 을 분모에서 잃는다 |
| **턴** (프롬프트 1회) | 페이로드 `prompt_id` | **701턴** · 도구 쓴 턴 404 · 셸 도구 쓴 턴 377 · 테스트 실행 턴 131 | ✅ 사람이 위임한 단위 그 자체. 코드 0줄로 식별 가능 |

**결정: 작업 단위 = 턴.** 근거 셋 — ①사람이 개입하는 자연 경계(프롬프트 = 위임)와 일치한다
②환경이 식별자를 이미 준다(추정·근사 없음) ③2주에 701 이라 분모가 선다. 세션은 턴을 묶는 상위
키로만 쓴다.

## 3. 정의 — 분모·분자·세 축

**분모 = 게이트가 본 턴.** pass 나 fire 가 하나라도 기록된 `turn`. 게이트를 안 지난 턴(질문·설명만
한 턴)은 "개입 없음" 이 아니라 **관찰 없음**이다 — 분모에 넣으면 비율이 부풀고, 공통 규약 4(안 잰 것
≠ 0)에 어긋난다. 실측: 701 중 377.

**분자 = 그 턴에 다음 세 축이 전부 참.**

| 축 | 정의 | 관찰 수단 | 상태 |
| - | - | - | - |
| ㄱ 게이트 개입 없음 | 그 턴에 프로브 아닌 `fire` 0 | 있음 — `turn` 필드로 집계 | 🟢 구현(§4) |
| ㄴ 사람 중단 없음 | 그 턴이 사람의 중단 없이 종료 | **없음** — 훅은 판정 지점만 본다. `Stop` 훅 연결 시 "정상 종료" 신호를 얻고, 다음 턴이 시작됐는데 Stop 이 없으면 중단(근사) | 🔴 훅 미연결 |
| ㄷ 검증 그린 | 그 턴 안의 마지막 검증 실행이 그린으로 끝남 | 부분 — 검증 명령의 실행은 게이트가 보지만 **결과(종료코드)** 는 PostToolUse 의 `tool_response` 구조를 실측해야 안다. 문서가 명시하지 않는다 | 🔴 실측 대기 |

세 축은 **따로 표기**한다. 하나만 있는 동안 "완주율" 이라 부르지 않는다 — 리포트는 `v2 턴(게이트
축)` 으로 적고 나머지 두 축이 미수집임을 같은 줄에 박는다.

### ⚠️ 게이트 축 하나로는 이 지표가 움직이지 않는다 — 기준선 실측

발동 15건을 턴에 대응시켰더니(시간창) **게이트가 본 턴 377 중 발동 있는 턴 14 · 없는 턴 363 =
96.3%.** 즉 v2 가 "상승" 을 보이려면 남은 여지가 3.7% 뿐이다. 게이트는 원래 드물게 발동하도록
설계됐으니(발동이 드물어 전수 판정이 가능한 것 — `13` §4) 당연한 결과이고, 그래서 **v2 의 완료를
게이트 축으로 재면 처음부터 거의 만점인 지표를 만드는 셈**이다.

움직이는 축은 나머지 둘이다. 트랜스크립트 실측(하네스 밖 관찰): 701턴 중 **사람이 중단한 턴 70
(10.0%)**, 테스트를 실행한 턴 131 — 이 둘이 "개입 없이 완주" 를 실제로 가르는 자리다. 따라서
**ㄴ·ㄷ 축이 붙기 전에는 v2 완료를 판정하지 않는다.** 지금 값(96.3%)은 기준선의 게이트 성분일 뿐이다.

## 4. 스키마 — additive 필드 셋과 짝짓기의 정확화

`13` §3 에 세 식별자 필드를 더한다(정의 불변, 이벤트 5종 그대로). 출처는 전부 훅 페이로드.

| 필드 | 페이로드 | 뜻 | 쓰임 |
| - | - | - | - |
| `session` | `session_id` | 세션 | 턴을 묶는 상위 키. (종전 환경변수 경로는 폴백으로 남긴다) |
| `turn` | `prompt_id` | 프롬프트 1회 | **v2 분모 단위** |
| `call` | `tool_use_id` | 도구 호출 1회 | `fire(ask)` ↔ `after` 의 **정확한** 짝 |

**짝짓기 정의의 변경 — 혼합 금지 적용.** 지표 2 의 승인 근사는 "같은 접두사 + 시간 순서" 였다.
`call` 이 있으면 같은 호출로만 짝짓고, `call` 이 있는 ask 는 근사로 떨어지지 않는다(그 after 도
`call` 을 갖고 왔을 것이므로, 접두사로 옛 after 를 집는 쪽이 남의 승인을 세는 오차다). 두 수는
`승인 N (정확 a · 근사 b)` 로 **따로** 낸다 — `13` §2 의 "정의를 바꾸면 그전 로그와 섞어 집계하지
않는다" 를 표기 분리로 지킨다. 승격 판정(`15`)의 짝짓기도 같은 함수를 쓰므로 함께 정확해진다 —
정확해지는 방향은 "짝을 더 못 찾는" 쪽이 아니라 "남의 짝을 안 집는" 쪽이라 `15` ⑥ 과 정합한다.

식별자 셋은 스키마 계약 검사(`13` §3 말미)에서 **원문 흔적 검사의 대상이 아니다** — UUID 형태가
정상이다. 빈 문자열은 위반(없으면 생략이 계약).

## 5. 완료 기준 — 전부 측정 가능해야 한다

| # | 기준 | 측정 방법 | 상태 |
| - | - | - | - |
| 1 | **식별자 셋이 실세션 로그에 실린다** | 골격 갱신 후 설치처의 새 이벤트에 `session`·`turn`·`call` 이 있다 | 🟢 실세션 관찰(2026-09-02 실측) — 설치처 두 곳의 자연 세션에서 turn 있는 이벤트 359·245, `v2 턴(게이트 축)` 40/40·34/34 무발동, 계약 위반 0. 세 번째 설치처는 그 뒤 세션이 없어 미수집(정직 표기) |
| 2 | **게이트 축 턴 지표가 리포트에 나온다** | `metrics.mjs` 에 `v2 턴(게이트 축)` 줄, turn 없는 이벤트는 제외 수로 표기 | 🟢 구현·테스트 |
| 3 | **ㄴ 축(중단) 관찰** | `Stop` 훅 연결 → 턴 종료 이벤트 → "다음 턴 시작 전 Stop 없음" 을 중단으로 집계. 이벤트 종류 추가는 `13` §2 정의 변경이므로 결정 이력 필수 | 🔴 설계 대기 — 이 문서의 다음 결정 |
| 4 | **ㄷ 축(검증 그린) 관찰** | PostToolUse `tool_response` 실측 → 종료코드가 있으면 검증 명령의 그린/레드 기록. 없으면 골격 2(`audit` 시계열)로 대체하되 골격 2 가 꺼진 설치처는 미수집으로 정직 표기 | 🔴 실측 대기 |
| 5 | **기준선 1점** | ㄱㄴㄷ 세 축이 모두 관찰되는 첫 2주의 비율 — 그 뒤의 "상승" 은 이 점 대비 | 🔴 3·4 뒤 |

v2 의 완료 판정은 기준 5 의 점이 생기고 그 뒤 실측이 그보다 **오르는** 것이다. 게이트 축 96.3% 는
기준선이 아니라 그 성분 하나다.

## 6. 이 문서가 다루지 않는 것

- 중단의 4갈래(영구 승인/1회 승인/거부/이탈) 구분 — `13` §2 의 관찰 한계 그대로. `Stop` 훅은 종료
  여부만 준다.
- 서브에이전트 턴(`SubagentStop`·`agent_id`) — 역할 경계(골격 3)의 실물이 생긴 뒤 붙인다. 지금
  설치처의 트랜스크립트엔 사이드체인이 0 이라 데이터가 없다.
- 턴의 "품질"(완주했지만 틀린 것) — 거짓 그린 감사(`13` §6 절차 2)의 몫이며 이 비율의 분자가 아니다.
