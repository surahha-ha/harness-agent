# v0 완료 기준 — 도달선

> **성격: 규범 문서.** 여기 적힌 기준은 구현이 못 미친다고 조용히 낮추지 않는다.
> 낮출 때는 이 문서에 근거를 적고 바꾼다. (서술 문서라면 코드가 이기지만, 도달선은 반대다.)

## 왜 이 문서가 있나

완료 기준이 없으면 골격을 다듬는 일이 끝나지 않는다 — "더 좋게" 는 종료 조건이 아니다.
그리고 이 기준은 뒤 단계(eval 하네스)의 **첫 측정 항목**을 겸한다. v0 이 끝났는지 재는 방법이
곧 하네스가 동작하는지 재는 방법이다.

## v0 에 넣지 않는 것 (경계)

- **골격 3(역할 경계) · 5(문서 규약) · 6(품질 사이클) · 7(배포 기계)는 절차 문서까지가 v0.**
  코드화는 v1 이후다. 근거: 이 넷은 발동 조건이 프로젝트 상황(역할 분화·짝 채널)에 있어,
  실물 없이 코드부터 쓰면 패널이 경고한 "만드는 사람의 시선" 으로 돌아간다.
- **패널 조건부 2건**(인계 기계검증 · 채널 1개 가정)은 v0 완료를 막지 않는다 —
  실물이 조건을 만들어야 닫히는 항목이라고 이미 판정했다.
- **eval·자동 최적화는 v0 밖.** 이 문서의 기준 1·2 가 그때의 첫 metric 이 된다.
  최종 목표(완전 자동화)까지의 단계 전체는 `08-roadmap.md` 에 있다.
