# 부트스트랩 — 새 프로젝트에 하네스를 까는 절차

목표는 **첫 30분에 가드 하나가 실제로 도는 것**이다.
전부 채우고 시작하려 하면 아무것도 시작하지 못한다.

---

## 0. 설치 모델

**복사해 넣는다(vendoring).** 패키지 의존으로 하면 특정 런타임 프로젝트에서만 쓸 수 있고,
전역 설치는 버전이 고정되지 않는다.

```
{프로젝트}/
  .harness/              ← 이 저장소의 skeletons/ 를 복사
  harness.config.mjs     ← 설정 (harness.config.example.mjs 를 복사해 채움)
```

복사본이 낡는 문제는 **골격 4(드리프트 감시)** 가 다룬다 — 그래서 이 모델과 골격이 서로 어긋나지 않는다.

## 1. 첫 30분

```
① 복사        skeletons/ → .harness/ · harness.config.example.mjs → harness.config.mjs
② 활성 확인    node .harness/danger-guard.mjs --status     ← 여기서 "비활성"이 나와야 정상
③ 채우기      아래 §2 의 5개 질문에만 답한다 (나머지는 비워 둔다)
④ 재확인      --status 가 "활성 — deny N · ask M" 으로 바뀐다
⑤ 훅 연결     도구가 명령을 실행하기 전에 가드를 부르도록 건다
```

⚠️ ②를 건너뛰지 않는다. **"비활성" 을 한 번 보고 가야** 나중에 그 메시지를 알아본다.
미설치와 통과는 겉보기가 같아서, 그 차이를 아는 것이 이 골격의 핵심이다.

## 2. 첫날 채울 다섯 칸

나머지 슬롯은 비워 둔다. 비어 있으면 그 골격이 안 돌 뿐 다른 골격을 막지 않는다.

| # | 슬롯 | 판별 질문 |
| - | - | - |
| 1 | `dangerGuard.deny` | **"실행 후 5분 안에 원상복구할 수단이 있나?"** 없는 명령 2~3개만 |
| 2 | `approvals.destructive` | **"이걸 잘못하면 누가 수습하나?"** |
| 3 | `commands.unitTest` | **"이 명령의 종료코드만 보고 통과/실패를 판정할 수 있나?"** (파이프 금지) |
| 4 | `project.repos.peers` | **"한쪽만 고치면 런타임에 깨지는 상대가 있나?"** 없으면 빈 배열 |
| 5 | `docs.always` | **"이 문서가 틀리면 누군가 잘못된 작업을 하나?"** |

⭐ **1번은 두세 개면 충분하다.** 완전한 목록을 만들려 하면 첫날이 끝나지 않는다.
가드는 사고를 겪을 때마다 규칙이 붙어 자라는 물건이다 — 그게 정상 성장 경로다.

## 3. 나머지 골격을 켜는 순서

한꺼번에 켜지 않는다. 각각 **켜기 전에 재는 절차**가 있다.

| 순서 | 골격 | 켜기 전에 할 일 |
| - | - | - |
| 1 | 위험 명령 가드 | 위 §1 |
| 2 | 문서 규약 게이트 | `docs.always` 를 정한다. 기존 위반은 유예(새로 추가된 것만 본다) |
| 3 | 드리프트 감시 | 짝이 있을 때만. **승인된 차이**를 먼저 목록화하지 않으면 경고 피로로 곧 꺼진다 |
| 4 | 품질 사이클 | `commands.*` 를 채우고, 경량 경로 탈락 조건을 팀과 한 번 읽는다 |
| 5 | test-first 가드 | **`--audit` 으로 먼저 센다.** 세지 않고 켜면 첫날 전부 막힌다 |
| 6 | 역할 경계 | 역할이 둘 이상 필요해진 뒤에. 혼자 다 할 때는 인계 비용만 는다 |
| 7 | 배포 기계 | 하네스를 두 번째 프로젝트에 깔 때. 하나뿐이면 배포할 것이 없다 |

## 4. 흔한 실수

- **전부 채우고 시작하려 한다.** 슬롯이 비면 그 골격만 안 돈다. 다섯 칸으로 시작한다.
- **`--audit` 없이 test-first 를 켠다.** 기존 코드가 전부 걸려 그날 꺼진다.
- **승인된 차이 목록 없이 드리프트 감시를 켠다.** 의도된 비대칭이 매번 경고로 나오고,
  사람은 곧 경고 전체를 읽지 않게 된다.
- **`deny` 만 넣고 `recover` 를 비운다.** 막힌 사람이 할 일을 모르면 규칙이 아니라 가드를 끈다.
- **`--status` 를 한 번도 안 본다.** 가드가 안 깔린 상태를 "위반 없음" 으로 몇 주 동안 믿게 된다.

## 5. 되돌리기

`harness.config.mjs` 에서 해당 골격의 `enabled` 를 `false` 로 두거나, 규칙 배열을 비운다.
`.harness/` 디렉토리와 훅 연결을 지우면 완전히 없앤 것과 같다.
**하네스는 프로젝트 코드에 아무것도 남기지 않는다** — 그래야 실험적으로 켜 볼 수 있다.
