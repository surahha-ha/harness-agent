# 부트스트랩 — 새 프로젝트에 하네스를 까는 절차

목표는 **첫 30분에 가드 하나가 실제로 도는 것**이다.
전부 채우고 시작하려 하면 아무것도 시작하지 못한다.

---

## 0. 설치 모델

**복사해 넣는다(vendoring).** 패키지 의존으로 하면 특정 런타임 프로젝트에서만 쓸 수 있고,
전역 설치는 버전이 고정되지 않는다.

```
{프로젝트}/
  .harness/              ← 이 저장소의 skeletons/ 를 복사
  harness.config.mjs     ← 설정 (harness.config.example.mjs 를 복사해 채움)
```

복사본이 낡는 문제는 **골격 4(드리프트 감시)** 가 다룬다 — 그래서 이 모델과 골격이 서로 어긋나지 않는다.

## 1. 첫 30분

```
① 복사        skeletons/ → .harness/ · harness.config.example.mjs → harness.config.mjs
② 상태 확인    node .harness/danger-guard.mjs --status
              → "설정됨 · 규칙 없음 — 아무것도 막지 않습니다"  ← 여기서 이게 나와야 정상
③ 채우기      아래 §2 의 5개 질문에만 답한다 (나머지는 비워 둔다)
④ 재확인      --status 가 "활성 — deny N · ask M" 으로 바뀐다
⑤ 훅 연결     §3 — 여기까지 해야 가드가 스스로 돈다
```

### `--status` 의 네 가지 대답

| 출력 | 뜻 | 종료코드 |
| - | - | - |
| `비활성 — 설정을 읽지 못했습니다` | **설치 안 됨.** 아무 검사도 하지 않는다 | 2 |
| `설정됨 · 규칙 없음 — 아무것도 막지 않습니다` | 설정은 있는데 **빈 껍데기** | 1 |
| `꺼짐 — enabled:false` | 의도적으로 끔 | 1 |
| `활성 — deny N · ask M` | 실제로 막는다 | 0 |

⭐ **두 번째를 "활성" 이라 부르지 않는 것이 핵심이다.** 설정 파일이 있다는 이유로 활성이라 보고하면,
아무것도 안 막는데 보호받는다고 믿게 된다 — **미설치보다 나쁘다.**
미설치는 의심이라도 하지만, 거짓 활성은 안심시킨다.

⚠️ ②를 건너뛰지 않는다. 그 메시지를 한 번 봐 둬야 나중에 알아본다.

## 2. 첫날 채울 다섯 칸

나머지 슬롯은 비워 둔다. 비어 있으면 그 골격이 안 돌 뿐 다른 골격을 막지 않는다.

| # | 슬롯 | 판별 질문 |
| - | - | - |
| 1 | `dangerGuard.deny` | **"실행 후 5분 안에 원상복구할 수단이 있나?"** 없는 명령 2~3개만 |
| 2 | `approvals.destructive` | **"이걸 잘못하면 누가 수습하나?"** |
| 3 | `commands.unitTest` | **"이 명령의 종료코드만 보고 통과/실패를 판정할 수 있나?"** (파이프 금지) |
| 4 | `project.repos.peers` | **"한쪽만 고치면 런타임에 깨지는 상대가 있나?"** 없으면 빈 배열 |
| 5 | `docs.always` | **"이 문서가 틀리면 누군가 잘못된 작업을 하나?"** |

⭐ **1번은 두세 개면 충분하다.** 완전한 목록을 만들려 하면 첫날이 끝나지 않는다.
가드는 사고를 겪을 때마다 규칙이 붙어 자라는 물건이다 — 그게 정상 성장 경로다.

## 3. 훅 연결 — 여기까지 해야 가드가 스스로 돈다

⚠️ **가장 빠뜨리기 쉬운 단계다.** ④까지만 하면 `--status` 는 "활성" 이라고 답하지만
**아무도 가드를 부르지 않는다.** 손으로 `--cmd` 를 칠 때만 도는 물건이 된다.

가드는 **명령이 실행되기 전에** 불려야 하고, 판정을 **stdout JSON** 으로 돌려준다.
연결 방법은 쓰는 도구마다 다르므로, 프로젝트가 가진 실행 지점에 맞춰 건다.

| 실행 지점 | 거는 법 |
| - | - |
| 에이전트 도구의 실행 전 훅 | 명령 실행 도구에 `node .harness/danger-guard.mjs` 를 연결. stdin 으로 도구 입력 JSON 을 받는다 |
| git 훅 | `.githooks/pre-commit` 등에서 호출하고 `git config core.hooksPath .githooks` |
| 셸 래퍼 | 자주 쓰는 위험 명령을 함수로 감싸 가드를 먼저 태운다 |

⚠️ **선행 조건 — 폴더 신뢰 승인.** 에이전트 도구는 신뢰 승인이 없는 폴더의 프로젝트 설정을
실행하지 않는다. 훅을 정확히 걸어도 승인 전에는 **로드조차 되지 않는다** — 아래 어느 확인으로도
이 상태는 보이지 않으므로, 연결 전에 대화형 세션을 한 번 열어 승인부터 한다.

**연결됐는지 확인하는 법 — 세 계층이 각각 다른 것을 본다.** 하나로 나머지를 대신할 수 없다.

| 계층 | 방법 | 보는 것 |
| - | - | - |
| ① 설정 | `--status` | 규칙이 읽히는가 |
| ② 프로토콜 | 훅이 줄 입력 JSON 을 stdin 으로 직접 파이프 | 명령줄과 입출력 형식이 맞는가 |
| ③ 발동 | **대화형 세션에서** 규칙에 걸리는 명령을 실행 | 도구가 실제로 가드를 부르는가 |

> ⭐ `--status` 는 **설정** 상태만 본다. **연결** 상태는 보지 못한다.
> 이 둘을 같은 것으로 읽으면 "활성인데 아무것도 안 막는" 상태를 못 알아챈다.

- ⭐ **③은 대화형 세션에서, 에이전트의 도구 호출로만 유효하다.** 두 대행 경로가 전부 거짓 음성이다
  (실측 — 필드 리포트 1 F9·F11): 헤드리스·자동화 경로는 훅이 아예 안 불리고,
  사용자 `!` 직접 실행도 도구 호출이 아니라 훅 경로를 타지 않는다.
- ⭐ **프로브 명령은 세 기준으로 고른다** (필드 리포트 1 F9·F12):
  1. **무해** — 훅이 죽어 실행돼도 아무것도 부서지지 않는다 (예: 존재하지 않는 경로에 대한 삭제).
     무해하지 않은 프로브는 검증이 실패하는 순간 그 실패가 곧 사고다.
  2. **대상 가드에만 걸린다** — 같은 패턴을 덮는 다른 가드(전역 훅 등)가 있으면
     차단돼도 **누가 막았는지 특정할 수 없다.** 하네스 가드가 죽어 있어도 그린으로 오판된다.
  3. **판정 메시지의 서명으로 주체를 확인한다** — 게이트 출력 계약("차단됨 — 이유 → 복구") 형식이
     떴는지 본다. 이 서명이 곧 발동 주체의 증명이다.

## 4. 나머지 골격을 켜는 순서

한꺼번에 켜지 않는다. 각각 **켜기 전에 재는 절차**가 있다.

| 순서 | 골격 | 켜기 전에 할 일 |
| - | - | - |
| 1 | 위험 명령 가드 | 위 §1 |
| 2 | 문서 규약 게이트 | `docs.always` 를 정한다. 기존 위반은 유예(새로 추가된 것만 본다) |
| 3 | 드리프트 감시 | 짝이 있을 때만. **승인된 차이**를 먼저 목록화하지 않으면 경고 피로로 곧 꺼진다 |
| 4 | 품질 사이클 | `commands.*` 를 채우고, 경량 경로 탈락 조건을 팀과 한 번 읽는다 |
| 5 | test-first 가드 | **`--audit` 으로 먼저 센다.** 세지 않고 켜면 첫날 전부 막힌다 |
| 6 | 역할 경계 | 역할이 둘 이상 필요해진 뒤에. 혼자 다 할 때는 인계 비용만 는다 |
| 7 | 배포 기계 | 하네스를 두 번째 프로젝트에 깔 때. 하나뿐이면 배포할 것이 없다 |

## 5. 흔한 실수

- **전부 채우고 시작하려 한다.** 슬롯이 비면 그 골격만 안 돈다. 다섯 칸으로 시작한다.
- **`--audit` 없이 test-first 를 켠다.** 기존 코드가 전부 걸려 그날 꺼진다.
- **승인된 차이 목록 없이 드리프트 감시를 켠다.** 의도된 비대칭이 매번 경고로 나오고,
  사람은 곧 경고 전체를 읽지 않게 된다.
- **`deny` 만 넣고 `recover` 를 비운다.** 막힌 사람이 할 일을 모르면 규칙이 아니라 가드를 끈다.
- **`--status` 를 한 번도 안 본다.** 가드가 안 깔린 상태를 "위반 없음" 으로 몇 주 동안 믿게 된다.
- ⭐ **④에서 멈추고 §3(훅 연결)을 안 한다.** `--status` 는 "활성" 이라 답하는데 아무도 가드를 부르지
  않는 상태가 된다. **설정과 연결은 다른 것이다.**
- **`{승인 주체}` 를 억지로 채운다.** 1인 프로젝트면 "본인" 이라 적거나 `null` 로 둔다.
  없는 승인 절차를 적어 두면 그 슬롯 전체가 장식이 된다.

## 6. 되돌리기

`harness.config.mjs` 에서 해당 골격의 `enabled` 를 `false` 로 두거나, 규칙 배열을 비운다.
`.harness/` 디렉토리와 훅 연결을 지우면 완전히 없앤 것과 같다.
**하네스는 프로젝트 코드에 아무것도 남기지 않는다** — 그래야 실험적으로 켜 볼 수 있다.
