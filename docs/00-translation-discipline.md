# 번역 규율 — 프로젝트 지식을 골격으로 올리는 방법

이 저장소의 헌법. **무엇을 골격으로 올리고, 무엇을 프로젝트에 남기고, 어떻게 옮기는가.**
새 자산을 추가하거나 기존 골격을 고칠 때 항상 이 문서를 통과시킨다.

---

## 0. 풀려는 문제

프로젝트에서 얻은 규율은 **구체적일수록 강하다.** "DB 검증은 조심해서" 는 아무도 안 지키지만
"검증 쿼리는 트랜잭션을 열어 마스터를 강제한다" 는 지켜진다.

그런데 구체는 그 프로젝트의 것이다. 여기서 두 갈래가 다 막힌다.

- **값을 지우면** — 남는 건 일반론이고, 일반론은 아무 사고도 막지 못한다.
- **값을 남기면** — 다른 프로젝트에 안 맞고, 저장소가 남의 정보로 오염된다.

> **해법은 지우는 것이 아니라 한 칸 올리는 것이다. 좌표는 빼고 메커니즘은 남긴다.**

특정 포트 번호는 그 프로젝트의 것이지만, **"읽기 라우팅을 경유하면 쓰기 직후 조회가 0행일 수 있다"** 는
아무의 것도 아니다. 어떤 리드 레플리카 구성에나 있는 현상이다.
**한 칸만 올리면 대부분의 사고 지식이 이전 가능해지고, 밀도는 그대로 남는다.**

---

## 1. 범용성 ≠ 범용화

둘은 반대 방향이다. 헷갈리면 저장소가 쓰레기로 찬다.

| | 범용성 | 범용화 |
| - | - | - |
| 정체 | 처음부터 아무 사고도 담기지 않은 문장 | 고유한 사고를 슬롯으로 추상화한 것 |
| 예 | "여백은 8의 배수로", "접근성을 신경쓰자" | "가드를 켜기 전에 `--audit` 으로 기존 코드가 몇 건 걸리는지 먼저 센다" |
| 출처 | 검색하면 나옴 | 무언가 깨져서 배움 |
| 판정 | **버린다** | **골격으로 올린다** |

"어디에나 맞는다" 는 가치의 근거가 아니다. **어디에나 맞는 이유가 아무것도 주장하지 않아서**일 수 있다.

### 엄격함의 소재 — 결정 (2026-08-18)

> **범용 골격은 판정 구조만 갖고 규칙을 갖지 않는다. 타이트함은 프로젝트가 사고와 실측으로만
> 채우며, 오탐률이 그 상한을 감시한다.**

흩어져 있던 원칙을 결정으로 못 박는다. 근거는 두 방향의 실패가 다 확인돼서다 —

- **범용 쪽이 타이트하면**: 레포에 박힌 구체 규칙은 프로젝트마다 안 맞아 구멍이 되고(§1 의
  범용화 실패), 과잉 규칙의 오탐은 경고 피로를 만들어 사람이 가드 전체를 끄게 한다 —
  타이트한 가드가 진짜 위험을 놓치는 경로다 (골격 4 의 경고 피로 서술 · F16 의 "겁을 줘서 위험").
- **그래서 견고함의 소재는 프로젝트다**: deny 는 첫날 2~3개로 시작해 사고마다 자라고(부트스트랩 §2),
  ask→deny 승격은 마찰 없음이 **실측**된 영역만(골격 1 승격 원칙), 이미 가드가 있는 자리에는
  켜지 않는다(F19 — 하네스는 빈 자리에만). v1 계측의 오탐률(지표 4)이 "너무 타이트함" 의
  조기 경보를 맡는다.

⚠️ 이 결정이 느슨하게 두지 **않는** 것 하나 — fail-closed·활성 확인 같은 **관찰성 장치는 고정**이다.
그것은 차단 강도가 아니라 "가드가 죽은 것을 보이게 하라" 는 요구이고, 느슨함과 침묵은 다른 문제다.

## 2. 지표 — 무엇이 골격이 될 자격이 있나

| 축 | 판정 질문 | 높음 | 낮음 |
| - | - | - | - |
| **P 사고 유래** | 실제로 무언가 깨져서 나왔나 | 측정 규율(허수 기준선이 정상 코드를 되돌리게 했다) | 여백 8의 배수 |
| **F 기계 판정** | 위반을 기계가 잡을 수 있나 | `deny`/`ask` 가드, 링크·경로 검사기 | "UX 를 신경쓰자" |
| **I 도메인 독립** | *성립하는 이유*가 도메인 밖에서도 유효한가 | 공유 계약이 있으면 커플링은 어디나 생긴다 | 특정 업종의 업무 규칙 |
| **S 슬롯 분리** | 고유명사·경로·임계값을 빼도 **뼈대가 남나** | 절차의 순서와 게이트가 뼈대 | 구체가 곧 내용인 지식 |
| **R 재발성** | 다른 스택에서도 같은 *유형*이 나나 | 미러 드리프트, 종료코드 오판 | 특정 도구의 고유 서식 |

### 절대 필터 둘

- **S = 0 → 골격 불가.** 값을 빼서 뼈대가 안 남으면 그건 절차가 아니라 **지식**이다. 프로젝트에 남긴다.
- **P = 0 → 반입 금지.** 사고에서 나오지 않은 문장은 **아무리 깨끗하고 범용이어도** 넣지 않는다.

F·I·R 은 정도 판정이다. 낮게 나오면 탈락이 아니라 **"슬롯을 더 깊이 파야 한다"** 는 신호다.

## 3. 추상화 사다리 — 고유 정보를 어떤 형태로 푸나

| 유형 | 골격에서의 형태 | 값의 행선지 |
| - | - | - |
| 저장소·서비스 이름 | `{BACKEND_REPO}` · `{FRONTEND_REPO}` | 프로젝트 설정 |
| 스키마·식별자 이름 | `{도메인 마스터 테이블}` · `{식별자 접두어}` | 프로젝트 경계표 |
| **인프라 좌표** (호스트·포트·컨테이너·계정) | **슬롯 이름만** — `{공유 DB 호스트}` · `{읽기 라우팅 포트}` | 프로젝트 설정. **저장소에 값이 오지 않는다** |
| 빌드·테스트 명령 | `{BUILD_CMD}` · `{UNIT_TEST_CMD}` · `{E2E_CMD}` | 프로젝트 설정 |
| **조직 신원** (계정·조직 URL·브랜드) | **슬롯 없음 — 삭제** | 없음 |
| **실패 서사** ⭐ | **메커니즘 문장으로 한 칸 올린다** | **골격 본문에 유지** |

### ⭐ 마지막 행이 이 문서의 핵심

실패 서사는 버리는 게 아니라 **번역한다.** 고유명사를 걷어내고 인과만 남기면 그대로 골격 자산이 된다.

| 원래 형태(프로젝트 고유) | 골격 형태(메커니즘) |
| - | - |
| 특정 포트가 읽기 프록시라 커밋 직후 조회가 비었다 | **읽기 라우팅/리드 레플리카를 경유하면 쓰기 직후 조회가 0행일 수 있다 → 검증은 마스터를 강제한다** |
| 특정 매퍼가 rename 때 누락돼 목록이 전멸했다 | **식별자 rename 시 조인 경로의 매퍼를 빠뜨리면 빌드는 통과하고 목록이 런타임에 전멸한다 → 매퍼 갱신은 조인까지 전수** |
| 빌드 로그를 tail 로 넘겨 실패를 통과로 읽었다 | **파이프로 넘긴 명령의 종료코드는 파이프 끝 명령의 것이다 → 결과는 리포트나 결과 줄로 확정한다** |
| E2E 실패 수가 실행마다 크게 달랐다 | **실패 시 아티팩트 덤프가 teardown 을 타임아웃 너머로 밀어 무관한 후속 테스트가 연쇄 실패한다 → 단일 실행으로 기준선을 확정하지 않는다** |

번역이 끝났는지 확인하는 질문 하나: **"이 문장을 처음 보는 사람이 어느 조직 이야기인지 알 수 있나?"**
알 수 있으면 아직 덜 올라간 것이고, 모르는데도 **무엇을 하지 말아야 하는지는 알겠으면** 번역이 끝난 것이다.

## 4. 3종 세트 — 하나라도 빠지면 실패한다

골격 자산은 항상 셋을 함께 갖는다.

1. **슬롯** — 프로젝트가 채울 빈 칸
2. **채우는 절차** — 그 빈 칸을 무엇으로, 어떻게 정하는가
3. **익명화된 실패 시나리오** — 안 지키면 무엇이 어떻게 깨지는가

| 빠진 것 | 결과 |
| - | - |
| ②③ 없이 ①만 | 무엇을 넣어야 할지 모르는 빈 템플릿 |
| ③ 없이 ①② | 왜 지켜야 하는지 몰라 바쁠 때 건너뛴다 |
| ①② 없이 ③만 | 남의 프로젝트 이야기 |

②③ 중 **③이 실제로 규율을 지키게 만드는 부분**이다. 분량이 아깝다고 제일 먼저 잘리는 것도 ③이라 명시해 둔다.

## 5. 게이트 — 오염을 사후에 치우지 않는다

1. **클린 저장소에 처음부터 쓴다.** 기존 자산을 복사해 놓고 치환하는 방식은 금지한다.
   치환은 항상 빠뜨리고, 빠뜨린 걸 찾는 비용이 새로 쓰는 비용을 넘는다.
2. **네 곳을 훑는다: 본문 · 주석 · 테스트 픽스처 · 매니페스트.**
   뒤 두 곳이 실제 누출 경로다. **가드 본문은 깨끗한데 그 가드를 검증하는 테스트가 실사례를 픽스처로 쓴다** —
   실사례여야 테스트가 진짜가 되니 구조적으로 반복된다. 매니페스트(author·homepage·repository)는
   사람이 안 읽어서 끝까지 남는다.
3. **픽스처는 합성 값만 쓴다.**
   - IP: **RFC 5737 예약 대역** `192.0.2.0/24` · `198.51.100.0/24` · `203.0.113.0/24`
   - 도메인·메일: **RFC 2606** `example.com` / `dev@example.com`
   - 식별자: `TBL_A` · `{도메인}_M` 같은 형태만
   합성 값으로 바꿔도 테스트의 진짜스러움은 줄지 않는다. 줄어드는 건 유출 가능성뿐이다.
4. **게이트를 이 저장소 자신의 커밋 훅으로 건다.** → `tools/scan-forbidden.mjs` · `.githooks/pre-commit`
   하네스가 자기 규율의 첫 적용 대상이다.
5. ⚠️ **금칙어 목록 자체를 커밋하지 않는다.**
   조직명·호스트·식별자 접두어를 모은 목록은 **그 자체가 유출물**이다.
   `.forbidden-terms.local`(gitignore)에 두고, 저장소에는 `.forbidden-terms.example` 만 남긴다.
   구조적 패턴(IP 리터럴·사설 대역·메일 주소)은 목록 없이도 스캐너가 잡는다.
6. **면제는 한 줄 단위로만, 표식을 남겨서.** 게이트 자신의 테스트 픽스처처럼 그 값이 있어야만
   성립하는 줄이 있다. 그런 줄에는 `scan-forbidden:allow` 를 붙인다.
   가드에는 탈출구가 있어야 하지만, 탈출구는 **`git grep` 한 번으로 전수 감사**되어야 한다.
   훅 자체를 `--no-verify` 로 건너뛰는 것은 면제가 아니라 회피다.

## 6. 적용 순서

새 자산을 골격으로 올릴 때:

```
①  P 와 S 를 먼저 본다            → 둘 중 하나라도 0이면 여기서 끝. 프로젝트에 남긴다.
②  슬롯을 판다 (§3)               → 고유값을 자리 이름으로 바꾼다
③  실패 서사를 번역한다 (§3 ⭐)     → 좌표를 빼고 인과만 남긴다
④  3종 세트를 확인한다 (§4)        → ③이 비어 있으면 미완성으로 표시한다
⑤  게이트를 돌린다 (§5)           → 0건이 아니면 커밋하지 않는다
```

②에서 막히면 대개 ①의 S 판정이 틀린 것이다. 슬롯이 안 파지는 자산은 절차가 아니라 지식이다.
