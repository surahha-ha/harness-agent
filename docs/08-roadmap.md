# 로드맵 — 최종 목표와 단계

> **성격: 규범 문서.** 방향 결정의 기록이다. 단계를 건너뛰거나 완료 기준을 낮출 때는
> 여기에 근거를 적고 바꾼다 (`07-v0-done.md` 와 같은 규칙).
>
> 결정 이력: 2026-08-14 — 최종 목표를 "완전 자동화 에이전트" 로 명문화.
> v0 까지는 목표를 "안전장치 + 구조화된 하네스" 로만 적어 왔고, 그 위 단계는 암묵적이었다.

## 최종 목표

**완전 자동화 에이전트** — 계획→구현→검증→보고를 무인으로 완주하고,
사람은 되돌릴 수 없는 지점의 승인(`{승인 주체}` 슬롯)에만 남는 상태.

v0 를 안전장치로 시작한 것은 우회가 아니라 경로다. 근거는 아래 원칙.

## 원칙 — 자율은 측정된 신뢰의 함수다

완전 자동화의 병목은 "에이전트가 일을 할 수 있느냐" 가 아니라
**"무인으로 맡겨도 되는지 어떻게 아느냐"** 다. 필드 리포트 1 의 발견 전부가 이 문제였다 —
거짓 활성(F1), 설정≠연결(F2), 헤드리스 거짓 음성(F9). 검증 없는 자율은
"잘 되고 있다" 와 "고장났는데 모른다" 를 구별하지 못한다.

> **자율의 범위 = 신뢰의 범위. 신뢰 = 측정의 함수.**
> 무인화할 범위를 넓히기 전에, 그 범위의 실패를 잡는 게이트와 계측이 먼저 있어야 한다.

골격 1 의 승격 원칙("마찰 없음이 **실측된** 영역만 ask → deny 로 올린다")을
자율성 전체에 적용한 것이다. 개입 없음이 실측된 영역만 무인으로 승격한다.

## 단계

| 단계 | 이름 | 내용 | 완료를 재는 법 |
| - | - | - | - |
| **v0** | 안전장치 | 골격 7종 + 가드 실발동 | `07-v0-done.md` 의 기준 5개 |
| **v1** | 계측(eval) | 하네스 위에서 에이전트 작업을 **재는 층** — 작업 완주율, 사람 개입 횟수·지점, 게이트 발동/오탐 비율 | 같은 작업 유형을 반복 측정해 기준선이 생긴다 |
| **v2** | 위임 확대 | 개입 지점을 데이터로 줄인다 — 역할 경계(골격 3)·품질 사이클(골격 6) 코드화, 습관적 승인만 남은 `ask` 의 자동 판정 승격, 인계 체크리스트의 스키마 승격 | "개입 없이 완주한 작업 비율" 상승이 실측된다 — 분모(턴)·분자(세 축)의 정의는 `16-v2-completion-metric.md` |
| **v3** | 자율 루프 | 계획→구현→검증→보고를 게이트 안에서 무인 실행 | 무인 완주 + 사후 감사에서 거짓 그린 0 |

**각 단계의 산출물이 다음 단계의 측정 도구다.** v0 의 가드·부트스트랩 시간이 v1 의 첫 metric 이고
(`07-v0-done.md` 가 이미 예약), v1 의 계측이 v2 승격의 근거이고, v2 의 개입 데이터가
v3 의 무인 범위를 정한다. 이 사슬을 끊고 단계를 건너뛰면 근거 없는 자율이 된다.

## 딥리서치 — v1 진입 시점에 함께 시작한다

일반론("다들 어떻게 하나")이 아니라 **실물이 만든 질문**을 들고 간다 —
상상으로 판 슬롯은 맞은 적이 없다(골격 7 의 한계 서술과 같은 이유). 현재 확정된 질문:

1. **에이전트 자율성의 eval 을 무엇으로 재는가** — 개입률·완주율 등 실무 지표와 측정 하네스
2. **자율 루프 실패 사례** — 초기 자율 루프 세대가 왜 실패했고, 후속 세대가 무엇을 바꿨나
3. **게이트 기반 자율성** — 사람 개입 지점을 점진 축소하는 구조를 실제 제품이 어떻게 구현하나

v1 설계 중 질문이 늘면 이 목록에 추가한다. 질문 없는 리서치는 시작하지 않는다.

## v0 와의 관계

이 문서는 v0 의 완료 기준을 **바꾸지 않는다.** v0 완주가 v1 의 선행 조건인 것은 동일하고,
번역 규율(프로젝트 고유값은 슬롯으로만)도 모든 단계에서 유지된다 —
자율 루프가 되어도 이 저장소에 들어오는 것은 형식뿐이다.
